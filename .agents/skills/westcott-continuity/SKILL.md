# Westcott 场次连续性

总导演在生成或续写前，先确定罗马尼亚日期、场次、当前任务和用户要求的范围。优先使用用户本轮明确提供的最新正文和决定，再读取与本轮直接相关的本地记录。

以下短名指 `westcott-state` MCP 的同名工具。若会话延迟加载工具，先发现以 `mcp__westcott-state__` 开头的对应工具。

## 接上次进度

用户只说「接上次进度」或「只看上次停点」时，直接调用 `get_resume_context`。默认传 `{}`，在有记录的最新布加勒斯特日期内查找。只添加用户明确给出的日期或场次，按所给条件筛选。按返回的 `status` 处理：

- `found`：简报日期和场次，分别说明已采用与实际已发的最后一句，累计条数仅在记录覆盖全场时报告。用已存节点、等待条件、待答项和下一步说明现在停在哪里。有轨道缺失就说「未登记」；若 `last_spoken_line_truncated` 为真，标明是摘录。用户需要完整末句时再查该场原断点。
- `choose`：列出候选日期、场次与已有轨道状态，包括已收场的场次，请用户选一项。用户选定后，带上该项日期和场次再次调用 `get_resume_context`，给出只读简报。
- `empty`：说明当前查找范围内没有已保存的场次停点。

如果工具不可用或读取失败，报告停点无法核对。只读交接以简报、候选或查询结果结束；它本身不触发读全文、编剧、核查、审稿、续写、发布或状态写入。用户另有明确续写要求时，识别场次后按原流程处理，并遵守仍有效的等待条件。

## 恢复顺序

1. 同场续写或补条数时，读取 `get_scene_checkpoint`，确认轨道、来源修订、已确认条数、最后一句、未解决问题和等待节点。
2. 新开课程时，读取 `get_agenda`，确定当前待办、已完成课程和下一课边界；必要时用 `read_record` 的 `tail` 读取上一课末段。
3. 场次交接时，读取 `get_handoff`，只承接已确认事项，避免把草稿、推测或未发送内容当作群内事实。
4. 需要成员连续性时，调用 `get_cast_context`，只向编剧和审稿传递本场所需的成员资料。
5. 需要财经事实时，调用 `get_fact_checks`；历史快照必须带原日期、时区和数据截点，不能直接改称“现在”。

## 任务分流

上面的只读交接直接用 MCP 查停点。其他请求读取 `reference/instruction-execution.md`，先归为局部改写、完整场次、现实事实、等待材料、状态写入或纯解释。局部改写不得扩大为完整场景；完整场次不能省略编剧和独立审稿；等待材料不能越过停点。

## 状态边界

草稿、采用、完成和已发送是四条独立轨道。读取任何记录时，先标明 `kind`、`track`、`status`、来源修订和用户确认文本。除非用户明确要求，不调用写工具。

遇到 `waiting` 停点时，只复述等待条件和下一步，不继续生成越过停点的正文。遇到版本冲突时，重新读取当前 revision，再决定是否仍符合用户最新要求。

## 课程与成长任务

先区分最终稿、备课草稿、教学模拟和未来安排。从最近真实采用的内容提取学员已经学到哪里、当前主课要讲什么、成长任务推进到哪、哪部分留待下一课。参考资料无法证实的进度保持待确认。

在讲知识点、分析案例、看图、答疑的过程中寻找课程与成长任务的交点。由内容决定发生位置和次数，把用户指定给后续课程的问题留到当晚再解答。到下一晚主动接回，明确学员这次应当理解或学会做什么。实际课程主题、进度和阶段任务以可验证材料及用户要求为准。

## 续写约束

续写必须从已确认正文的最后一句或明确节点接入，并保留尚未回答的问题和当前任务边界。只改指定条目时，不得顺手重写整场；用户要求完整场景时，才按 `reference/instruction-execution.md` 进入完整编排流程。
