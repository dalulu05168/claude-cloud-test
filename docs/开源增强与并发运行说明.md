# MCP 诊断与并发运行说明

## MCP Inspector

Inspector 是可选诊断工具。从项目目录运行相应命令检查本地 `westcott-state` 的握手与工具列表。

Windows PowerShell

```powershell
.\tools\inspect-mcp.ps1 -Mode cli
```

macOS、Linux、WSL2

```bash
bash tools/inspect-mcp.sh cli
```

诊断脚本通过 `npx` 调用固定版本 Inspector 2.16.0。支持 Node.js 22.23.4 起的 22.x、24.22.1 起的 24.x，以及 26.12.1 起的版本。缺少 npm 或暂时离线时，可用 `node tools/self-test.mjs` 自查本地 MCP。详见 [Inspector 2.16.0](https://github.com/modelcontextprotocol/inspector/releases/tag/2.16.0) 和 [Node.js 版本范围](https://github.com/modelcontextprotocol/inspector/blob/2.16.0/package.json#L150-L152)。

`web` 和 `tui` 模式允许手动调用 MCP 工具。交互测试请在单独的项目副本中进行，Inspector 直接连接 MCP 服务，写入工具会使用该副本的状态目录。日常 Claude Code 会话中的写入确认由项目 Hook 负责。

## 并发诊断

`tools/concurrency-smoke.mjs` 默认并行启动 4 个独立 MCP 进程，验证每个连接的初始化、工具列表和 `ping`。可以传入 2 至 16 个连接。输出中的 `writes_tested: false` 表示此项检查仅覆盖连接；状态写入与修订冲突由 `tools/self-test.mjs` 在隔离目录中覆盖。

```powershell
node tools/concurrency-smoke.mjs
node tools/concurrency-smoke.mjs 8
```

## 开源工具的用途

Claude Code 负责启动和关闭项目的 stdio MCP 进程。PM2、`mcp-proxy-tool` 和 Multi-Agent Observability 原先用于评估长期驻留、远程桥接和独立观测服务，本项目的日常桌面流程可直接使用本地 stdio 和项目诊断脚本。

## Claude Code 连接检查

图形界面在 Claude Desktop 的 **Code → Local** 打开项目。终端可用 `claude mcp list` 或交互命令 `/mcp` 查看 `westcott-state`，用 `/hooks` 查看 Hook。完整连接与验证步骤见 [桌面版安装与运行说明](../桌面版安装与运行说明.md)。
