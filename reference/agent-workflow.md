# 基础版出稿规则接入

基线为 `westcott-efficient-workflow` 2.3.2，仓库提交 `257820d527038aaf8b04b6c156ee916f1f7f3408`。原样快照在 [base-workflow](base-workflow/SKILL.md)。本项目使用该快照中的写作、校验和课件规则，继续使用项目的 Claude Code Agents、MCP 和状态确认。基础版提到的 Python 记忆工具属于其独立运行方式。本项目只使用 `westcott-state` 写课稿和场次进度。

## 写稿前

1. 先按用户范围和布加勒斯特日期确定场次。白天与周日复盘读取 [导演](base-workflow/references/director.md)，新闻与活动读 [助理](base-workflow/references/assistant.md)，用到角色读 [成员](base-workflow/references/members.md)。晚间课从 [晚间入口](base-workflow/references/evening.md) 分流，五项职责是模块，按需读。局部改写只加载必要片段和 [编写规则](base-workflow/references/writer.md)。
2. 续写和补条数先确认 Google 文档当天页签最新末段或用户给出的最新正文。若访问失败，说明缺口并用用户确认的本地原文进行可完成部分。断点里的下一步和待答事项是前情数据；以本轮场次规则决定何时、由谁接续。查询已保存进度仍走只读 MCP。
3. 总导演给编剧明确日期、场次、实际起点、是否含开群、允许角色、条数、节点、已核事实和停点。周一、三、五下午的默认角色为助理与成员，固定下午欢迎句，上午有竞猜时提醒交顾问 Gabriela，由 Gabriela 核对通知，助理不在群里揭晓。成员穿插在三条资讯间。到当天换算出的美股开盘节点接用户给的推票材料，缺材料停在节点前，不提前闭群，默认不播美股开盘价。可用开盘时间工具核对当天时区换算，周一三五仍按推票流程定停点。周二、四按基础版的判断题与开盘截图流程。先生只按本场允许的教学环节或用户另有明确安排出场。
4. 普通新闻用助理标签、国旗与国家财经新闻标题、事实段、影响及关注段，提供官方图的直链和来源页。获取不到官方事件图时依助理模块说明并提出官方替代。精确盘中时间留在核查记录。美股开盘卡、昨晚收盘回顾、活动、推票材料按各自格式。先生段落按适用教学模块。新编编号对话保留教学模拟标识；新场默认 01–52、53–65 仅点名局部编辑。不要伪造实际成员回答、持仓或交易记录。

## 新闻选题和缺证据的处理

- 从正式公告、公司新闻室、交易所、统计机构等主动找可用原文。遇到 403、矛盾或找不到首发时间，换一条可读的官方或权威来源核查。同一来源正文打不开时，搜索摘要不能当作已核实。
- 普通下午资讯按布加勒斯特当地当天首发及已播顺序筛选。隔日报价和转载旧业绩不能单独充当当天新消息。保留它们需要独立核实当天的实质更新，且只把旧事实作为清楚标注的背景。
- 在用户指定的改稿范围内，先保留能核实的选题；不够时主动找当日合规的替代新闻。只有用户明确锁定选题、全部可用检索都受阻，或证据不足无法达到原定条数时，报告具体缺口并交付已经核实的部分。无需让用户提供普通公开链接或在不合格的稿件选项中选择。
- 优先找官方事件图。基础版允许与事件主体直接对应的官方替代图，例如涉事公司官网的 Logo；在稿外注明替代类型及来源页。无关图、不同报告期的图和占位均不可用。格式通过只表示链接和版式通过。
- 出稿前逐条使用 `validate_news_broadcast`，传实际日期、场次、播报截点和 `require_source_evidence: true`。必须提供已查阅的原始来源 `source_url`、带时区的 `published_at`、实际核查的配图直链和来源页，并在 `image_check.relation` 标明 `event` 或 `official_subject`；无关图标 `unrelated` 并从稿中剔除。再把返回的 `expected_news` 交给格式校验。独立审稿核对实际证据支持的事实、配图关联和时效。若 Stop 只报配图结构错误，回到证据核查或改用其他合格选题。

## 写完后

- 参照 [检查契约](base-workflow/references/contracts.md)，对整场或每日稿调用快照内的 `scripts/review_draft.py`（带实际日期，晚课加 `--scope evening`，片段加 `--fragment`）。对标号稿先定契约，再用 `scripts/check_scene.py`。当天完整出稿或续写时，按 [成员规则](base-workflow/references/members.md) 对授权文档导出运行 `silence_check.py`。普通短编辑按基础版走局部检查。运行这些脚本需要 Python 3.9+，缺少运行环境或文档历史时，报告对应未完成的检查。
- 调 `validate_scene_count` 时传实际日期、`scope`，包含开群才传 `starts_scene: true`。周一三五下午只有用户明确增加先生环节时传 `allow_teacher: true`；只有按基础版完成推票且为补其后的成员互动才传 `recommendation_followup: true`。基于现实资讯的完整稿另用已核新闻条目检查标题、顺序和图。机器通过后，编辑核对语义、节点和事实边界，尤其不要把竞猜揭晓、后台等待和读到的旧待答问题擅自写进开场。
- 报告实际运行的校验和未核项。由用户确认后才写入状态。Google Docs 写入和群内实际发送按各自回执登记，不能从本地采用状态推断。
