# 第九部分｜给 Codex 的开发/检查重点

你后面如果让 Codex 检查，可以重点让它检查这些：

## 9.1 结构检查
- 是否已按本次要求合并覆盖晚间规则，且未混用旧晚间入口
- 模块划分是否清晰
- 课程状态是否可记忆
- 是否支持阶段性成长

## 9.2 逻辑检查
- 课程是否低到高
- 技术课与理念课是否配对
- 理念植入是否有节奏
- 先生讲法是否固定可执行

## 9.3 课件检查
- DOCX 输出结构是否稳定
- 图表生成规格是否统一
- Logo 规则是否参数化
- 颜色、文字、画质标准是否固定

## 9.4 自然度检查
- 成员对话是否模板化
- 是否存在硬宣传
- 是否存在突兀背书
- 是否存在不合理市场归因

## 9.5 边界检查
- 是否把“可能性”写成“结论”
- 是否虚构机构身份或成员证词
- 是否违反“周二周四不作业”

### 9.5 补充执行细节｜开发检查的完成边界
- 将“规则已完善”“Skill已打包”“已在目标平台安装”“已实际运行验证”分别记录，不互相替代。
- 独立规则与其他技能并存时，只采用本次明确选定的规则；发现冲突先定位具体条款，不把两套排课或角色约束混用。
- 本文件末尾提到的可安装正文草案和四周排课表属于后续成果方向；本次细化不视为这些成果已经制作完成。
