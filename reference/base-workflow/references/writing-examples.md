# 写作校准与语义验收

以下是新编的校准样例，不是用户已认可范文、人物历史或真实投资记录。只在首次校准、用户指出文风问题或任务需要时读对应例子，不每次读全表。以后用户认可的真实范文按来源、日期及适用场景保存，不能由AI自行盖章“已认可”。

| 输入/要求 | 合适处理 | 不应处理 |
|---|---|---|
| “只改第二条” | 只交付第二条，保留其数字、条件和立场 | 顺便重写第一条或补结尾 |
| “如果昨日80万股，今日120万股，增幅应该是50%，对吗？” | “昨天80万股，今天120万股，那成交量就是多了50%，对吧？” | 写成“股价涨了50%”或删去疑问 |
| “我可能明天再看。” | “我也许明天再看看。” | “我明天会买。” |
| “等待开盘，不闭群” | 完成已允许片段，在未知数据前停下 | 加“我们晚上见”或编开盘结果 |
| 两位教学角色对同一概念有疑问 | 一位问比较基准，一位确认适用条件 | 人人复述同一结论或统一表达信服 |
| 讲“成交量较昨日增加” | 说明比较基准；常态是否异常需其他数据 | 直接推断未来价格上涨 |

同一场里长短要有参差：上面“可以怎么写”一栏多数是短句，实际写的时候也要有人连发两条、有人只回一个表情、有人认真写一长段提问。

## 交付前语义检查

按任务只检查相关项，每项需要具体句子或输入依据，不能统一自评“全部优秀”。

1. 意义：立场、条件、不确定性、时间与比较对象是否变化？
2. 范围：交付的是指定部分吗？是否新增未经要求的课程、行动或结尾？
3. 连续性：上一段发生的事是否有来源？人物能否知道尚未公布的信息？
4. 表达：是否重复相同功能，或为了区别人物虚构口癖/经历？
5. 事实：模拟、引用、推断和实际记录是否区分？数字一致不等于事实已核实。

发现具体问题只修对应句，再检查受影响项；最多两轮，不为追求“更自然”无限改稿。机器结构检查通过后仍需这一步，语义检查也不能代替权威来源核验。

## 语义核对方法

局部改写把原句和新句逐项比较：主体、行动、时间、条件、否定、不确定性、数量与证据状态。尤其检查“可能→确定”“观察→买入”“计划→完成”“曾买入→已卖出”。程序检查数字不等于完成这些检查。

内部记录发现的问题所对应的原句、新句和影响，只修具体问题。无法判断时标记待确认，不输出虚假的语义PASS；普通短编辑不向用户附一整张审查表。多人对话还检查重复功能、未公布信息、教师是否实际回答了疑问。
