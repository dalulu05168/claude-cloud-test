# 目标应用的行为验收集

这些是虚构测试输入，不是项目正式历史。升级后在实际目标应用逐项执行，记录版本、输入、实际输出、工具回执、通过/失败/未执行及原因；没有实际输出不得填通过。脚本回归与下列模型行为分别验收。

| 编号 | 输入/操作 | 通过条件 |
|---|---|---|
| A01 局部编辑 | 提供三条正文，要求只改第二条“我可能明天再看，价格是120。” | 仅返回第二条；可能性、明天、观察及120不变，不写成明天买入 |
| A02 多人表达 | 给同一个模拟成交量例子，要求四名角色独立短评，不提供人物经历 | 关注点可含观察、犹豫、不同意见、疑问；不把一个意思换词写四遍，不杜撰持仓或家庭，也不强制四种句式各一条 |
| A03 教师回应 | 前文一人问比较基准、一人问是否预示上涨，要求教师一起解释 | 回答两个疑惑，讲具体机制与推论限制，不只复述问题或喊口号 |
| A04 续写停点 | 采用稿停在等待开盘，要求补两条但仍等待、不闭群 | 保留模拟标识，新增两条，不编行情/结果、不收尾 |
| A05 候选隔离 | 保存仅有candidate_text的检查点，新聊天说继续 | 不把候选称已采用；起点不明确时先确认，不自动编已完成条数 |
| A06 来源变更 | 旧检查点source_revision为r1，当前提供r2且末段变化 | 按r2核对续写，不重复r2已完成的环节，不以旧next_step覆盖本次要求 |
| A07 跨聊天恢复 | 聊天A保存测试项目的已采用末段、候选、未解问题、停点；同机新聊天B明确使用本技能恢复该项目 | B实际运行resume读取正确项目与版本，正确区分候选与已采用，按停点继续；必须保留工具回执 |
| A08 双窗口冲突 | A/B均读revision N，A保存N+1，B按N提交不同变更 | B失败且A内容保留；B重新读取、核对差异，不强行改版本覆盖 |
| A09 多项目 | 同一目录存在两个项目，仅说继续且未指定 | 不按最近修改时间自动选择，先询问项目 |
| A10 缺权限/损坏 | 新聊天无法访问目录或文件损坏 | 明确未恢复，不称记得；不重新初始化或覆盖坏文件 |
| A11 证据边界 | 仅给买入标注，要求总结已卖出利润 | 指明缺卖出依据，不生成已获利见证 |
| A12 旧入口 | 指定目录内保留旧skill与新版 | doctor报告候选重叠入口及启用状态未验证，不称已停用；实际平台由用户核对 |
| A13 BVB休市 | 要求写11月30日或12月1日（罗马尼亚法定假日）的上午场 | 先核对BVB休市；不写BVB开盘播报、不写10:20盘前截止，改为节日问候、美股/欧洲资讯和成员聊天 |
| A14 周一三五推票节点 | 周一下午文档已有23条，用户给出推票卡片，要求补到闭群 | 先读文档数条数；3条资讯已齐才接推票；推票卡片→公司简介→成员发言（不少于4—5句，可超38）→闭群；不播开盘数据、不写“已买”、不发开盘前速览 |
| A15 绿涨红跌 | 要求助理播报一只盘中上涨、一只盘中下跌的股票，并让成员和先生各评一句 | 涨用绿、跌用红；盘中不说“收绿/收红”，用“见绿/飘红”；三方颜色一致 |
| A16 晚间节奏 | 要求写一段先生讲两张图和成员回应 | 先生连讲两三段后由成员集中回应，不一句成员一句先生；回应人数和位置可变，先生可先抛问题让成员猜；常见概念追问可当堂集中解释，复杂质疑留后续已安排答疑 |
| A17 晚间闭群 | 周一三五先生已实际布置练习，要求助理闭群 | 三句结构；第二句为当晚课程要点并提醒把练习交给Gabriela；助理不另布置作业 |
| A18 成员口吻 | 要求6位成员对“除息后价格下跌”各说一句 | 质疑/反问多于附和；“这个懂”“记下了”类最多一句；可联系派息、国债、汇率等本地关切；不编持仓、收益或中国成语 |
| A19 出场分布 | 要求写上午、下午、晚间三场 | 全天出场20—30人；同场有人说两三句、有人一句，不是几乎每个编号各一句；@人用名字不用编号 |
| A20 晚间市场分析 | 当天有重大数据（如CPI偏热），要求写晚间先生开课 | 选择与课题相关的已核事实及可能解释，只有证据支持时分析罗马尼亚传导；无合适案例不强套，互动围绕真实理解难点 |
| A21 编排不雷同 | 连续两天写同一场次 | 开场句式、猜题/答题的互动、成员回应排列、结尾方式明显不同；至少一处成员间分歧或纠正 |
| A22 开盘卡片 | 用户发来美股开盘卡片要求播报 | 逐项核对卡上数字与前收；播报数字与卡片一致；不另做卡片 |
