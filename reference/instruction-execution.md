# Claude 指令执行契约

总导演每轮先判定交付范围。涉及出稿前先用 [基础版出稿规则接入](agent-workflow.md) 锁定场次、星期、开场、角色、节点和停点。查到的旧交接不能改变本场流程。现实事实核查可作为独立任务，也可以是完整场次中某些段落的前置步骤。状态写入取决于用户对对应动作的明确要求。用户最新明确要求优先于历史草稿，相关确认和校验按本表执行。

## 执行前登记的四个字段

在调用工具或子 Agent 前，先在内部确定四项内容：

| 字段 | 必须回答的问题 |
| --- | --- |
| `scope` | 本轮是只读交接、局部片段、完整场次、财经核查、等待材料，还是状态写入？ |
| `must_call` | 本轮必须调用哪些读取工具、校验工具或子 Agent？ |
| `must_not_call` | 本轮明确禁止调用哪些写入工具、扩大范围或发布动作？ |
| `exit_condition` | 交付、等待、询问或保存分别以什么条件结束？ |

若无法确定范围且会影响交付，只询问一个最小的澄清问题；不要用猜测替代缺失的日期、场次、稿件范围或用户确认。

## 任务分流表

| 任务类型 | 识别信号 | 必做动作 | 通过条件 | 明确禁止 |
| --- | --- | --- | --- | --- |
| 只读交接 | 「接上次进度」「只看上次停点」等，仅定位之前的工作 | 直接调用 `get_resume_context`，只传明确指定的日期或场次。按 `westcott-continuity` 简报已知停点；有候选时请用户选一项 | 报出停点、候选、没有记录或无法核对 | 不读全文、不调子 Agent、不续写、不发布、不写入状态 |
| 局部改写 | 用户指定一句、一个角色、一个条目或明确行号 | 只读取必要原文；按指定范围改写；校验角色格式和口吻 | 输出未超出指定范围，且保留用户要求保留的原文 | 不调用完整编剧/审稿流程；不读取无关历史；不写入状态 |
| 完整场次 | 用户要求完整晚课、完整多人场景、收尾或实质性续写 | 读取任务线、场内断点、前文、成员上下文；调用 `westcott-writer`；调用格式和口吻校验；调用 `westcott-editor` | 编剧稿已生成，格式/口吻校验通过，编辑审稿为通过或阻塞项已修复并复检 | 不把草稿直接当作已采用或已发送；不跳过独立审稿 |
| 现实事实核查 | 用户要求核实一项现实财经主张，或稿件依赖未核的公告、行情、首发时间等 | 单独核查时直接调用 `westcott-verifier`。完整场次中把核查证据交给依赖它的稿件段落。按所需范围核对原始来源、时区、时间口径及新闻配图 | 每项主张有证据状态。待核或冲突内容在交付时明确标出 | 仅凭“今天”等日期词触发核查，或把历史快照当成当前数据 |
| 等待材料 | 用户要求等开盘、等材料、等成员确认，或已有停点明确要求等待 | 读取当前断点并复述等待条件；必要时保存仅经用户明确确认的停点 | 明确写出 `status: waiting`、`stop_after` 和下一步 | 不继续生成超出停点的内容；不擅自推进任务线 |
| 保存草稿 | 用户明确说“保存这版为草稿” | 核对稿件 ID、场次和当前任务；调用 `save_draft` | 写入结果读回并报告草稿 ID；仍标记为草稿 | 不登记采用、完成或已发送 |
| 采用片段/稿件 | 用户明确说“采用、确认可用、按这版继续” | 先确认采用范围；调用 `record_adoption`；片段需要时保存 adopted 断点 | 采用范围、正文和断点一致 | 不因片段采用推进整课；不写 sent 状态 |
| 完成整课 | 用户明确确认整课完成，且已有覆盖整课的 adopted 版本 | 读回 adopted 记录和任务线；调用 `complete_lesson`；读回下一待办 | 只推进一项当前任务，并能提供完成记录 | 不把局部片段、草稿或未审稿版本当整课完成 |
| 实际已发送 | 用户明确确认某段已发到群内 | 保存 sent 轨道和对应事项；核对实际发送范围 | sent 记录与已发正文、条数和时间一致 | 不把 adopted 或 draft 改名为 sent |
| 仅解释/分析 | 用户只问规则、原因、步骤或项目状态 | 只读必要文件和记录，给解释或诊断 | 没有不必要的内容生成或状态变更 | 不调用写入工具，不生成可发送稿件 |

## 子 Agent 调用门槛

用 Claude Code 的 `Agent` 工具按名称调用。完整场次、完整多人场景和实质性续写必须调用 `westcott-writer`，之后必须调用 `westcott-editor`。如有待核的现实财经事实，再调用 `westcott-verifier`。只读交接、局部改写、纯解释、等待材料和仅保存草稿沿用各自的阅读与交付范围。用户在局部请求中明确加上事实核查时，可以只调用核查员，并只修改指定范围。

核查员无法访问网页时，导演可以使用当前会话已获准的网页能力或用户提供的原文取得证据，再交给核查员复核。单独核查到此交付所查主张、证据与待核缺口，无需进入完整场次流程。项目工具短名均指 `westcott-state` MCP 的工具，例如 `mcp__westcott-state__get_agenda`。

如果子 Agent 不可用，不能把本轮标记为完整流程已通过。总导演可以根据已有资料给出**临时稿**，但必须在稿外标明未启动的代理、未完成的检查和仍需人工确认的事项；不得声称已经完成独立审稿或事实核查。

## 状态写入门槛

`save_agenda`、`save_draft`、`record_adoption`、`complete_lesson`、`save_scene_checkpoint`、`save_handoff`、`save_fact_check`、成员记录和手机稿导入均属于外部状态写入。只有用户在当前会话明确要求相应动作时才调用。用户说“看看、准备、给我一版、先别保存”均不是授权。

状态必须保持以下区分：

> **草稿**表示生成过；**采用**表示用户确认可用；**完成**表示当前任务对应的完整课已确认结束；**已发送**表示用户确认实际发到群内。四种状态不能互相推断或覆盖。

写入前必须核对当前 revision；写入后必须读回结果。遇到版本冲突，重新读取后只重试仍与用户最新确认一致的操作。

## 交付前检查顺序

完整场景按以下顺序收尾：

1. 核对范围、场次、任务线和停点没有被扩大。
2. 核对事实状态、来源、发布时间、时区、数据截点和配图证据。
3. 调用格式验证，检查角色标记、新闻结构、教学格式、条数和配图行。
4. 调用口吻验证，检查中文群聊节奏、套话、炒作和股票黑话。
5. 调用 `westcott-editor`，修复阻塞项并只复检改动相关段落。
6. 确认本轮应交付的是稿件、临时稿、等待说明还是状态写入结果。
7. 只有用户明确要求时才执行写入，并读回确认。

Stop hook 只负责拦截可机械判断的格式和口吻问题，不能替代任务分流、子 Agent 调用、事实真实性或用户确认。
