# ELLERY WESTCOTT · Claude Code 桌面版

这套项目可从 Claude Desktop 的 Code 本地会话使用。当前会话按基础技能直接处理，独立审稿用 Haiku 的 westcott-reviewer。本地 MCP 保存任务线、课程记录、场内断点、早午晚交接、财经核查记录、手机导入的稿件与成员档案。

从旧版升级时，先关闭旧项目。把新版解压到单独目录，若旧项目有 `.westcott-state`，把整个文件夹复制到新版项目下，再启动新版。已有草稿、旧版登记为完成的课及其任务线照原记录读取。需要用旧草稿登记新完课时，核对范围后把完整版本保存为整课稿，再确认完成。若上一版自行收录过额外范文，把对应条目从旧版复制到 `reference/writing-samples/`，并把索引条目合并进新版。

## 写稿规则版本

本项目执行基础版 2.3.2 的场次、角色、播报与晚课规则，并使用本地 MCP 记录进度。见 [基础版出稿规则接入](reference/agent-workflow.md)。新包沿用旧版状态目录，已保存的采用和已发记录无需重建。

## 在 Claude Desktop 打开

1. 解压完整 ZIP，保留根目录的 `CLAUDE.md`、`.claude`、`.mcp.json` 和 `tools`。安装 Node.js LTS，确保系统能找到 `node`。在已登录的 Claude Desktop 进入 **Code → Local → Open folder…**，选择含这些文件的项目目录。若显示 Worktree，保持关闭，让不同会话读取同一个本地状态目录。桌面版 Code 有自己的引擎版本，可用 `/status` 查看，完整的 Hook 失败阻断要求 Claude Code 2.1.295 或更新版本。[Claude Desktop 快速入门](https://code.claude.com/docs/en/desktop-quickstart) · [桌面版引擎版本](https://code.claude.com/docs/en/desktop#claude-code-version-in-the-code-tab)
2. 首次打开时信任已核对的项目目录。有项目 MCP 授权提示时，批准 `westcott-state`。普通 Claude 会话读取项目指令和基础技能。从会话请求读取本地计划，并在工具调用记录核对 `get_agenda`；新目录显示空计划即可。[项目默认 Agent](https://code.claude.com/docs/en/sub-agents#work-with-subagents) · [项目范围 MCP](https://code.claude.com/docs/en/mcp#project-scope)
3. 需要读取 Google 文档时，再通过 Code 的连接器界面启用已获准的 Google Drive。也可以提供目标页签的原文。只有实际返回目标日期的原文，才能据此承接和引用。[桌面版连接器](https://code.claude.com/docs/en/desktop#connect-external-tools) · [Google Drive 连接器说明](https://support.claude.com/en/articles/10166901-use-google-workspace-connectors)

CLI 启动器、项目预检命令和故障排查见 [桌面版安装与运行说明](桌面版安装与运行说明.md)。

## 第一次运行

在 Desktop 的会话活动中检查独立审稿是否调用脚本并返回了结果。演练只使用给定的假设条件。

> 做一段独立的 Westcott 教学模拟。写一段包含多人互动的回踩课堂中段，假设价格跌破支撑后又收回。让成员提出一个判断问题，先生回答并说明接下来怎么确认。交稿前用 westcott-reviewer 审稿。只交稿，不保存。

如果要验证 Google Drive，另发这一句，并查看 Claude 所引用的原文。

> 读 Google Docs《===== D资讯助理 =====》11 月 17 日晚间课程，给出课程主题、一个成员问题和原文链接。只读。

若连接器只读到其他标签页，贴所需标签页链接和对应段落。原文未经确认时，当前会话应明说能读到哪部分。

## 每天怎么用

- 首次确认本阶段的任务线时，发 `把我刚确认的阶段和课程顺序保存为潮汐蓝图。日期未定的先留空。`。当前会话会回读并确认已保存的第一项待办。以后调整顺序或本课边界时，明确说要更新计划。
- 换窗口先找停点时，从同一项目目录打开新会话，说「接上次进度」。当前会话只查询有记录的最新布加勒斯特日期。只有一场就分别报采用和已发的末句、已知条数、等待条件和下一步。有多场就列出候选，等你选定。要查更早的一场，可以加日期和场次。这一步只读，确认方向后再发续写指令。
- 同一场换窗口后，从同一项目目录打开会话，说 `继续今天下午。` 或 `继续今晚的课。`。有场内断点时，当前会话读取已确认原文、条数和等待节点，再按原范围续写。开始下一课时读出任务线和上一堂完课稿。完整晚课及实质性多人教学段落会交给 Haiku 的 westcott-reviewer。
- `把刚才这版保存为草稿。` 让本地 MCP 写草稿。
- `这段可以用，按现在的停点保存。` 保存采用正文和同场断点，仍沿用本课待办。出现多稿时，用 ID 指明采用哪一版。
- `采用这份完整课稿，我确认本课完成，推进任务线。` 登记整课完成。只在合稿覆盖本课任务且已对应任务线时推进到下一项。
- `刚才开场的两条已发，记下实际发到哪一句。` 保存已发断点。正式稿及修订可从 Google 文档核对。采用、整课完成和已发分别保存。

## 场次交接与财经核查

上午确认实际发过的资讯和还待处理的事，就能让下午和晚间读取这些事项。例句：`记一下罗马尼亚时间今天上午：刚才那条 BVB 资讯已发，竞猜还等 Gabriela 核对。` 下午确认竞猜已核后，按同一事项更新。晚间可直接说 `接今天白天的进度，起草晚间开群。` 草稿采用和实际已发各自有据。默认交接会查看近七天仍待处理的事项。

财经核查可发 `核实这条消息并留档，写清发布时点、公告原文和行情截点。` 查同一天的盘前稿时，按准确日期和盘段读取。需要当前点位，再发起最新核查。核查记录中的历史快照应带原时间。状态为冲突或待核时，出稿注明资料不足，或暂时省去该句。

按 [运营记录](reference/operations.md) 处理开盘、休市、推荐、竞猜、作业及交接。局部改写只取指定正文和必要前文。续写先取场内断点和需要的原稿末段。Claude Code 压缩后的恢复示例见 [按任务读取与续写](reference/writing-context.md)。

新闻先选对罗马尼亚金融市场或 BVB 有重大影响的事件，再选美股重大动向。按布加勒斯特首发时点排序，核对前夜例外、事件图与原文的对应。场次及默认成员范围读取 [统一配置](reference/scene-rules.json)。详见 [新闻规则](reference/news-broadcast-policy.md)。

助理每条财经新闻一次给出三段：国家和事件标题、事实描述、关键影响与后续关注。正文下方附一行对应事件的已核配图直链。David 每次发言一次给出两段：先说明判断和证据边界，再解释逻辑及如何验证。两位各保留固定角色标记，段间空一行。详见 [助理与先生发言规范](reference/speech-format.md)。

所有角色发言用中文，采用罗马尼亚人在 WhatsApp 投资群里直接、简短、就事论事的聊天节奏。避免中式群聊套话、股票黑话及炒作。成员通常用一句短句，表情零或一个。见 [中文发言口吻](reference/whatsapp-voice.md)。

## 手机与电脑接力

云端项目加载新版本后，可在会话里问「查今天候选稿到了哪一步，有没有缺证据」。需要回看历史时，可以说「查‘回踩’上次在哪堂课讲过，带原文链接」。定时新闻候选和历史索引使用执行机的私有状态目录。详见[历史检索与候选稿交接](reference/agent-workflow.md#历史检索与候选稿交接)。

1. 手机上确认一版后，按 [手机交接说明](reference/mobile-handoff.md) 的模板，把标题、停点和正文追加到指定的 Google Docs 交接箱。
2. 回电脑打开项目会话，说「接手机稿，先看有哪些确认稿」。它读取交接箱，给出条目编号、正文和停点。看到想接着用的稿件，再说「把编号 `…` 导入本地草稿」。同一版和同一任务关联重复导入时返回原草稿。
3. 继续改稿或预览时保留草稿状态。确认采用片段时可保存为同场断点。需要推进任务线时，把覆盖整课的合稿保存为完整课稿，再明确确认本课完成。

## 验收跨课和独立审稿

用单独解压的目录试跑，避免把示例混入正式任务线。先让当前会话保存以下两项测试计划，再开新会话，只说「继续今晚的课」。

> 测试阶段目标是让学员理解观察机构交易线索的用途。第一项是形态课，讲回踩时同步带出观察机构线索，留给下场回答为什么。第二项是投资理念课，回答为什么要跟踪机构。按这个顺序保存两项测试任务，日期先留空。

第一场由当前会话按基础技能出稿，课堂正文应在读图、讲解或成员提问时带出机构线索。完整晚课应看到 `westcott-reviewer` 的只读审稿回执。先只采用一个中段并保存断点，另开窗口发「继续今晚的课」，应恢复该段末句，待办依然是形态课。完整形态课稿采用且明确确认本课完成后，再开下一场，应该接到「为什么要跟踪机构」。

还可以在测试目录登记一个下午断点，让它停在「等美股推票材料」。换窗口后应读出同样的末句、条数和待办，保持等待。若只确认开场已发送，查询时应分别显示已发开场和采用稿的两个停点。

试用同一采用稿编号重试追加，条数应保持不变。更新正式稿修订后，再查末句和条数，应以核对到的新正文为准。最后一条是带配图的新闻时，继续写从最后一句台词接入。

历史 Google Docs 如果把 `===== 资讯助理 =====` 或老师的标记与台词写在同一行，读取后仍应独立计数、识别末句角色。重复发言按原文保留。

窗口内用 [压缩示例](reference/writing-context.md#压缩-claude-code-对话) 保留同一断点，再说「只继续同一场，先说接在原文哪一句后面」。核对它从已确认台词续写，待答的机构问题依然留在原排定的课次。另试「只改第二条，保留 1,25% 和其它原文」，核对输出范围和数字。

## 编剧样本库

当前会话按基础技能和场景查找 [写作样本](reference/writing-samples/index.md)。目前有 17 日用户认可的晚课、18 日原稿参考，以及三组新写的改前改后教学对照。已有样本可以在本地读取。要增加范文，指定认可的原稿及范围，例如「把这版晚上 20:00 之后的讨论收进编剧样本库，重点保留成员怎么接住先生的问题」。

要试验写法，发「照 17 日晚课里‘用新证据让成员重新判断’的方式，写一个新的回踩课堂中段。给一个能改变原判断的明确条件。交稿前确认成长任务在对话中完成，并用 westcott-reviewer 审查格式与口吻。」核对结果是否用了本场场景，是否出现具体条件，以及 Claude Code 是否调用了 `westcott-reviewer`。

## 成员口吻和出场管理

项目内置已确认的 65 人最终表。姓名、编号、性别和昵称从原表读取，默认出场名单按 [统一配置](reference/scene-rules.json)。编稿时只向子 Agent 传本场相关人员。

需要补写作设定时，给当前会话编号和你认可的口吻，例如「确认记录 12 男的写作设定：常用一句短问追实际判断条件。例句是『那先看收盘？』」。这是教学剧本的写作设定。

你确认要留下某场记录时，可以说「在这版已采用的教学稿里，记一下 12 男在晚间问过‘下次先看收盘能不能守住吗？’，这个问题留到下一场」。下次写相关场景时，当前会话会查看该成员最近出场、学到哪和问过什么，再按本场安排怎么接话。真实群内反馈有独立查询范围。

具体字段和验收方法见 [成员口吻与出场](reference/member-cast.md)。

成员可按已确认的讨论倾向分为质疑组、观望组、信随组或其他组。新人记录按实际场次从提基础问题，逐渐过渡到说观察、用条件和自己修正判断。当前会话按成员已经学到的部分安排发言。

## 课件和形态图

对一份已采用的课稿说「用这版生成课堂课件、形态图和课后练习」。当前会话会读到这堂课，用 `build_lesson_kit` 生成浏览器课件、SVG 形态图、讲师提纲和学生练习。双击输出的 `lesson.html` 就能翻页，下载 3840×2160 PNG，或通过浏览器打印为 PDF。

图表用绿涨红跌。比如原课只讲到第四根 K 线跌破，第五根只是设问，图上将第五根放进标明的假设区。讲师参考答案保存在单独的 `teacher-notes.md`。

输入格式和图表示例见 [课件生成说明](reference/lesson-kit.md)。

## 本地检查

在该目录 PowerShell 运行 `node tools/self-test.mjs`。它使用临时目录和独立进程验证 27 个 MCP 工具，覆盖旧记录、课程完成、场次和手机交接、局部修改范围、成员、新闻顺序、配图、开盘时区及休市处理。双窗口续写、连接器授权和子 Agent 实际运行可以在 Claude Desktop 的 Code 本地会话核对。


## 指令执行强化配置

本版本在原有 Westcott 业务规则之上增加了项目级 Claude Code 执行契约。每轮请求先按 `reference/instruction-execution.md` 分流；完整场景由当前会话按基础技能出稿，交 Haiku 的 `westcott-reviewer` 运行 `review_draft.py` 并检查口吻。实时事实另行取证，委派查资料只用 Haiku。局部改写、等待材料和纯解释不会自动扩大为完整场景。

项目在 `.claude/settings.json` 注册 Stop 和 PreToolUse，并通过 `command` 与 `args` 直接启动 Node。Stop 检查可机械判断的角色格式、新闻段数、配图 URL 形状、David 段数和中文口吻问题。PreToolUse 在修改计划、稿件、采用、完成、交接、核查或成员记录前请求当前用户确认。[Claude Code Hook 命令配置](https://code.claude.com/docs/en/hooks#command-hook-fields)

当前工作流使用 `westcott-efficient-workflow` 作为唯一写稿规则来源，审核 Agent 只读。草稿、采用、整课完成和实际已发送保持为四种独立状态。

### 验收命令

在项目根目录运行：

```powershell
node tools/health-check.mjs
node tools/health-check.mjs --json
node tools/verify-hooks.mjs
node --test tools/confirm-state-write.test.mjs .claude/skills/westcott-stop-gate/scripts/stop-gate.test.mjs .claude/skills/westcott-stop-gate/scripts/analyze-stop-gate.test.mjs
node tools/self-test.mjs
```

`health-check.mjs` 检查 Node 版本、关键文件、Hook 注册、PreToolUse 的失败阻断配置、脚本语法、Stop 和 PreToolUse 的本地响应、状态目录访问权限以及临时目录。检查使用本地脚本和测试数据。`--json` 便于机器读取。退出码 `0` 表示通过或只有警告，`1` 表示检查失败。

`verify-hooks.mjs` 在本地验证 Hook 注册、正常与受拦截的输出、只读 MCP、状态写入提示和非法 JSON 的响应。它只使用测试输入。

可用桌面新建会话验收项目加载、状态读取和子 Agent 返回。要核对持久化写入前的确认提示，用单独解压的测试项目保存一份测试草稿，并在确认弹窗选择拒绝，随后查询确认没有新增记录。另测完整晚课、局部改写和重新打开会话后取回断点。CLI 提供 `/hooks` 和 `/mcp` 供排查。
